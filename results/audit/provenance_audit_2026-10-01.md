How the splits work:

- **Organ models**: `train_organ_generic.py` filters the pool to one dataset, then calls `patient_split`. The split is per patient.
- **Tumor models**: `train_tumor_ausam.py:66-69` also filters, then splits.
- **Records and the 3-D tumor eval** (`build_predicted_corpus.py:90-92`, `eval_tumor_3d.py:44-49`) use the **unfiltered global** tumor split, in pool order pancreas, lits, flare, kits. Because `numpy` shuffle consumption depends only on list length, the global test sets for lits, flare and kits differ from the training splits.
- All seeds are 42; all splits are per patient (no slice-level splitting).

## 4. The split defect claim

**Verified.** `eval_ausam_3d.py:159-161` filters to one dataset before calling `patient_split`. `eval_crossdataset_organ.py:33-34` calls `patient_split(M)` on the whole pool. The shared split function (`train_organ_generic.py:33-48`) keeps one RNG running across datasets.

| dataset | test patients shared between the two scripts | crossdataset test patients that are in the model's TRAIN / VAL |
|---|---|---|
| LiTS (first in pool order) | 6/6, identical | — |
| MSD | 14/33 | 14 / 5 |
| KiTS | 4/20 with the delivered capped pool | 14 / 2 |
| FLARE23 | 19/89 | 64 TRAIN |

- The reviewer-reported "3/20" figure is what the *uncapped* 131/281 pool gives.
- The empirical numbers agree. The crossdataset diagonal equals the in-distribution result only for LiTS (0.9567 = 0.9567). It differs for KiTS (0.9114 vs 0.9266), MSD (0.8766 vs 0.8713), and both FLARE sets.
- **Training split**: `train_organ_generic.py --ausam --dataset` filters too (lines 91-98), so it **matches eval_ausam_3d**. The organ 3-D DSC test sets (ausam_3d_*) are therefore disjoint from training patients. I reproduced all five test lists and the slice counts.
- **What is contaminated**: the crossdataset_organ.json diagonal and the off-diagonal "held-out" cells.
- **Same defect class for tumors**: tumor_3d_{lits,kits,flare23}.json and the 113-case/576-case predicted corpora.
